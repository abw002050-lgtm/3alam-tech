سمعت كثيرًا بكلمة **GitHub** لكن لا تعرف ما هي بالضبط؟ أنت لست وحدك. في هذا الدليل سنشرح Git و GitHub ببساطة تامة.

## ما هو Git؟

**Git** هو نظام لتتبّع التغييرات في الملفات. تخيّل أنه "حفظ بالإصدارات" — كل مرة تعدّل ملفًا، يحفظ Git نسخة، ويمكنك العودة لأي نسخة سابقة متى شئت.

> **مثال:** تكتب مقالًا. تعدّل فقرة. ثم تندم وتود العودة للأصل. مع Git، العودة تتم بأمر واحد.

## الفرق بين Git و GitHub

| | Git | GitHub |
|---|---|---|
| **ما هو** | أداة محلية على جهازك | منصة على الإنترنت |
| **يحتاج إنترنت؟** | لا | نعم |
| **يدعمه؟** | مفتوح المصدر | Microsoft |
| **البديل** | — | GitLab, Bitbucket |

ببساطة: **Git** يحفظ التعديلات محليًا، و**GitHub** يرفعها للسحابة لمشاركتها مع العالم.

## لماذا تحتاج GitHub؟

- **معرض أعمال**: كل الكود في مكان واحد — يراه أصحاب العمل
- **تعاون**: عدة أشخاص يعدّلون نفس المشروع دون فوضى
- **نسخ احتياطي**: كودك محفوظ على خوادم GitHub
- **استضافة مجانية**: GitHub Pages يستضيف موقعك مجانًا
- **مفتوح المصدر**: آلاف المشاريع لتتعلّم منها

## المصطلحات الأساسية

| المصطلح | المعنى بالعربي |
|---------|----------------|
| **Repository (Repo)** | مستودع — مجلد المشروع |
| **Commit** | التزام — حفظ نسخة من التعديلات |
| **Push** | دفع — رفع التعديلات لـ GitHub |
| **Pull** | سحب — تنزيل تعديلات الآخرين |
| **Clone** | نسخ — تنزيل نسخة كاملة من مشروع |
| **Branch** | فرع — نسخة موازية للتجربة |
| **Merge** | دمج — توحيد الفروع |
| **Fork** | تشعيب — نسخ مشروع غيرك لحسابك |

## أول مشروع على GitHub (من الهاتف)

### الخطوة 1: إنشاء المستودع

1. افتح [github.com](https://github.com) وسجّل دخولك
2. اضغط زر **+** أعلى اليمين → **New repository**
3. سمّه `first-project`
4. اجعله **Public**
5. فعّل **Add a README file**
6. اضغط **Create repository**

### الخطوة 2: تعديل ملف عبر المتصفح

1. اضغط على `README.md`
2. اضغط أيقونة القلم ✏️ للتعديل
3. اكتب:

```markdown
# مشروعي الأول

مرحبًا! هذا مشروعي على GitHub.

## عني
- أتعلّم البرمجة
- من اليمن 🇾🇪
```

4. اضغط **Commit changes**

🎉 مبروك! أول commit لك.

## أوامر Git (للحاسوب)

لو تستخدم حاسوبًا، ثبّت Git من [git-scm.com](https://git-scm.com)، ثم:

```bash
# تنزيل مشروع
git clone https://github.com/username/repo.git

# الدخول للمجلد
cd repo

# تعديل ملف (مثلاً بإضافة ملف جديد)
echo "مرحبًا" > hello.txt

# إضافة الملف للمرحلة
git add hello.txt

# حفظ التغيير
git commit -m "إضافة ملف ترحيب"

# رفع التعديل لـ GitHub
git push origin main
```

## سير العمل النموذجي

```
تعديل الملفات → git add → git commit → git push
```

هذه الدورة تتكرر مع كل تغيير. مع الوقت تصبح تلقائية.

## نصائح مهمة

- **commit message واضح**: اكتب "إصلاح زر الدخول" لا "تعديل"
- **commit صغير**: كل تغيير مستقل، لا تدمج أمورًا كثيرة
- **README جيد**: اشرح مشروعك في ملف `README.md`
- **.gitignore**: استبعد ملفات لا تريد رفعها (مثل كلمات المرور)

## هل أحتاج Git لكل شيء؟

لا. للمشاريع البسيطة، التعديل المباشر على موقع GitHub كافٍ. لكن للمشاريع الحقيقية، Git ضروري.
